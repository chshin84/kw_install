# kw_install

새 PC 한 대에 클로드 코드와 문서 작업 도구를 한 번에 세우는 설치기다. 이 폴더만 복사하면
된다. 다른 폴더를 참조하지 않는다.

## 좋은 점

- **한 줄 실행.** 무엇을 깔지 고르거나 답할 것이 없다.
- **회사망 자동 판정.** 사내 SSL 검사 장비가 있는 PC면 인증서를 세우고, 없으면 세우지 않는다.
  담당자에게 묻지 않는다.
- **되풀이해도 안전.** 이미 된 것은 건너뛴다. 집에서 깔고 회사에서 다시 돌려도 된다.
- **접속을 확인한 뒤의 성공 보고.** 붙어 보지 못하면 성공이라고 말하지 않는다. 마지막에 실제
  HTTPS로 접속해 본다.

## 먼저 할 일

**PowerShell 7을 Microsoft Store에서 설치한다.** 이 설치기는 PowerShell 7을 스스로 깔지
못한다. 자기가 돌아갈 판이기 때문이다. Windows PowerShell 5.1로 물러서지도 않는다.

## 실행

일반 사용자로 연 창에서 돌린다. 관리자로 띄우지 않아도 되고, 관리자로 돌리면 클로드 코드가
그 관리자 계정의 폴더에 깔린다고 경고한다.

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
```

`setup.cmd`를 더블클릭해도 된다. 같은 것을 실행한다.

무엇이 일어날지만 먼저 보려면 이렇게 한다. 아무것도 깔거나 쓰지 않는다.

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 -WhatIfOnly
```

`-Ssl Yes` 와 `-Ssl No` 로 인증서 판정을 직접 덮어쓸 수도 있다. 붙이지 않으면 설치기가 스스로
잰다.

## 마친 뒤에 할 일

**터미널·VSCode·클로드 창을 닫았다 다시 연다.** 환경변수와 PATH는 레지스트리에 바로 들어가지만,
이미 떠 있는 창은 시작할 때 물려받은 옛 값을 그대로 들고 있다. 마무리 화면이 창을 닫았다
열라고 하는 이유가 이것이다.

새로 연 창에서 업무 폴더로 옮겨 `claude` 를 치면 클로드 코드가 뜬다.

같은 이유로 auto 모드도 **클로드를 새로 켜야** 실린다. 실행 중인 세션은 시작할 때의 모드를
그대로 들고 가고, 이어 붙인(resume) 세션도 마찬가지다.

바탕화면에 놓인 `PowerShell 7` 바로 가기는 오른쪽 클릭해 작업 표시줄에 고정해 두면 다음부터
편하다. 이 한 번은 윈도우 11이 스크립트로 하는 고정을 막아 두어 사람이 직접 해야 한다.

## 잘 안 될 때

무엇이 잘못됐는지는 화면에 찍히는 종료 코드로 알 수 있다.

| 코드 | 뜻 |
|---|---|
| 0 | 끝났다. 다만 터미널 단계는 실패해도 설치가 계속되므로, 그 단계에 노란 줄이 있었는지 화면에서 함께 본다 |
| 1 | 설치기가 예상하지 못한 곳에서 멈췄다. 마지막으로 찍힌 단계 이름이 어디서 멈췄는지 알려 준다. 전체가 멱등이므로 원인을 고친 뒤 그대로 다시 돌린다 |
| 2 | 인증서 재료를 모으지 못했다. 기존 번들은 건드리지 않았다 |
| 3 | 마지막 검증에서 실제 접속이 되지 않았다. 세 갈래이며 바로 아래에서 가린다 |
| 9 | 더블클릭 진입점이 낸 것이다. PowerShell 7을 찾지 못했거나 `setup.ps1`이 옆에 없다. 화면에 해결 방법이 함께 나온다 |

**종료 코드 3으로 끝났다면** 세 갈래 가운데 하나다. 번들을 구운 PC라면 환경변수는 섰으나 그
번들로 붙지 못한 것이다. 인증서가 필요 없던 PC라면 이 PC가 아예 인터넷에 못 붙은 것이다.
노드만 실패했다면 클로드 코드가 서버에 닿지 못한다는 뜻이므로 `-Ssl Yes` 로 다시 돌린다.

**설치가 끝난 뒤에 HTTPS가 계속 실패한다면** 사내 루트 인증서가 이 PC의 윈도 저장소에도 없다는
뜻이다. 그때는 윈도에서 인증서를 내보내 `certs\` 에 넣고 다시 실행한다. 방법은
`certs\README.txt` 에 적혀 있다.

**회사망 밖에서 깔았다가 나중에 회사에서 걸린다면** 그냥 다시 실행하면 된다. 전체가 멱등이라
두 번 돌려도 안전하다.

## 설치 단계

열 단계를 순서대로 지난다. 화면에는 `0/9`부터 `9/9`까지 번호가 함께 찍히며, 번호가 0부터
시작하므로 `7/9`는 아래 표의 여덟째 줄이다. 아래에서는 번호가 아니라 이름으로 부른다.

| 단계 | 하는 일 |
|---|---|
| 사전 점검 | pwsh 판과 winget이 있는지, 관리자로 돌고 있는지를 확인한다 |
| 인증서 | 가로채기가 있는지 재고, 필요하다고 판단되면 번들을 굽고 환경변수 4종을 세우며 curl 설정 한 줄을 넣는다. 잴 재료가 아직 없으면 프로그램 단계 직후로 미룬다 |
| 프로그램 | 파이썬 3.12(판 고정)와 git, Node.js LTS, Poppler를 winget으로 깐다 |
| 파이썬 라이브러리 | 고정한 3.12를 사용자 PATH 맨 앞으로 옮긴 뒤, `requirements.txt`에 적힌 것을 그 안에 넣고 `pip check`로 충돌을 확인한다 |
| Claude Code | 사용자 프로필에 설치한다. 관리자로 승격하지 않는다 |
| PATH | `%USERPROFILE%\.local\bin`을 사용자 PATH에 넣어 `claude`를 이름만으로 실행하게 한다 |
| 터미널 | 윈도우 터미널의 글꼴을 굴림체 10으로, 글자 가장자리를 다듬지 않게 맞춘다. 그리고 파워셸 7 프로필을 바로 여는 바로 가기를 시작 메뉴와 바탕화면에 놓는다. 여기서 실패해도 설치는 계속된다 |
| 클로드 연동 | 스킬을 복사하고 도커 훅을 등록하며 `settings.json`과 `CLAUDE.md`를 병합한다 |
| 플러그인 | 마켓플레이스를 등록하고 플러그인 다섯을 설치한다. 이전 판이 복사해 둔 `document-formats` 스킬 사본은 그 플러그인이 확인된 뒤에 사본을 남기고 걷어낸다 |
| 검증 | 실제 HTTPS로 붙어 본다. 번들을 구웠으면 그 번들만 신뢰하도록 강제하고, 안 구웠으면 이 PC의 기본 신뢰로 붙는다. 파이썬에게 한 번, 클로드 코드가 도는 노드에게 `api.anthropic.com`으로 한 번 따로 묻는다 |

**인증서가 맨 앞인 이유.** 그 뒤로 네트워크를 타는 모든 것이 사내 SSL 검사 장비를 지난다.
신뢰가 서지 않은 PC에서는 그 전송이 실패한다. 프로그램이 안 깔리는 것이 아니라, 그 프로그램이
내려받아야 할 파이썬 라이브러리와 플러그인이 안 들어온다.

**검증이 맨 뒤인 이유.** 붙어 보지 못하면 성공했다고 말하지 않는다. 실패하면 종료 코드 3으로
끝난다. 검증에는 파이썬이나 노드가 필요하고, 프로그램 단계가 둘 다 세우는 이유가 이것이기도
하다.

## 이 PC에 생기는 변화

프로그램과 파이썬 라이브러리, 그리고 클로드 코드의 플러그인과 스킬이 들어온다. 사용자 파일은
다섯을 고친다.

- 클로드 코드의 `settings.json`
- 클로드 코드의 `CLAUDE.md`
- 클로드 코드의 플러그인 레지스트리 `known_marketplaces.json`
- 윈도우 터미널의 설정
- curl 설정 파일 `.curlrc`

`.curlrc` 를 뺀 넷은 통째로 덮지 않고 필요한 값만 고치며 고치기 전 사본을 `.bak` 으로 남긴다.
`.curlrc` 에는 줄을 덧붙이기만 하고 사본은 남기지 않는다.

무엇을 왜 넣었는지, 설정 파일의 어느 줄이 어떻게 바뀌는지, 어떤 파일과 환경변수가 어디에
놓이는지는 `docs\CHANGES-ON-THIS-PC.md` 에 항목별로 적혀 있다.

## 덮이지 않는 것

- **WSL과 도커 컨테이너.** 별개 환경이라 윈도우 사용자 환경변수를 물려받지 않는다. 컨테이너에는
  번들을 `COPY`하거나 마운트하고 그 경로를 `REQUESTS_CA_BUNDLE` 등으로 가리켜야 한다. 번들을 구운
  PC라면 도커 명령을 낼 때 이 사실을 알리는 훅이 클로드 연동 단계에서 등록되고, 번들이 없는
  PC에는 가리킬 곳이 없어 등록되지 않는다.
- **CA 경로를 코드에 박은 라이브러리.** 환경변수를 무시하므로 호출부를 고쳐야 한다.
- **SYSTEM으로 도는 스케줄 작업.** 사용자 스코프 변수를 보지 못한다.
- **PowerShell 7 자체.** 이 설치기를 돌릴 판이라 스스로 깔 수 없다. 먼저 깔아야 한다.
- **브라우저 자동화의 스크립트 경로.** `playwright` 플러그인은 깔지만 전용 브라우저를
  내려받는 `python -m playwright install chromium`은 하지 않는다. 시간이 걸리고 사내망에서
  막히기도 해서, 매일 자동으로 도는 도구를 만드는 단계에 가서 붙인다.
- **담당자에게 물어서 채우는 개인 기억.** 클로드 연동 단계가 `templates\personal-memory-ko.md`를
  사용자 `CLAUDE.md`에 병합하기는 하지만, 그 내용은 모든 PC에 같게 들어가는 고정 문안이다. 이
  담당자가 어떤 사람이고 무엇을 하는지 묻고 받아 적는 절차는 이 폴더에 없다.

## 이 폴더에 있는 것

| 경로 | 역할 |
|---|---|
| `setup.ps1` | 본체다. 판단과 검증을 전부 갖고 있다 |
| `setup.cmd` | 더블클릭용 진입점이다. pwsh 7을 찾아 `setup.ps1`에 넘기고, 못 찾으면 코드 9로 끝낸다 |
| `requirements.txt` | 파이썬 라이브러리 목록의 정본이다. 제약마다 이유가 적혀 있다 |
| `claudecode-color.png` | 바로 가기 아이콘의 원본이다. 설치기가 이것을 `.ico`로 구워 쓰고, 지우면 아이콘이 조용히 파워셸 것으로 물러선다 |
| `certs\` | 공용 인증서 목록(`combined_cacert.pem`)이 들어 있다. 파이썬이 없는 새 PC에서 인증서 판정을 하려면 이것이 있어야 한다. 회사 인증서는 이 PC의 윈도 저장소에서 가져오므로 없는 것이 정상이며, 언제 채우는지는 `README.txt` 에 적혀 있다 |
| `hooks\docker-cert-reminder.ps1` | 도커 명령 훅의 본체다. 등록할 때 각 PC로 복사된다 |
| `skills\register-corp-certs\` | 인증서 지침의 정본이다. 도커 훅이 이것을 가리킨다 |
| `templates\` | 참고 자료가 아니라 실행 중에 읽히는 입력이다. 마무리 안내(`closing-ko.txt`), 문의처(`support-ko.txt`), 그리고 사용자 `CLAUDE.md`에 병합되는 개인 기억 블록(`personal-memory-ko.md`)이 들어 있다. 지우면 안내가 영어로 물러서고 개인 기억 병합이 죽는다 |
| `tests\test_setup.ps1` | 계약을 검사한다 |
| `docs\CHANGES-ON-THIS-PC.md` | 이 PC에 무엇이 들어오고 무엇이 바뀌는지를 항목별로 적어 두었다 |
| `docs\DESIGN-NOTES.md` | 왜 그렇게 만들었는지를 적어 둔 설계 메모다 |
| `docs\superpowers\reviews\` | 문서를 고칠 때 받은 검진 기록이다. 설치기가 읽지 않는다 |
| `Claude Code 설치 가이드.url`·`Claude Code 실행 가이드.url` | 사내 안내 문서로 가는 바로 가기다 |

이 표에서 셋 — `certs\combined_cacert.pem`, `certs\README.txt`, `docs\DESIGN-NOTES.md` — 은
사내 공유폴더에만 있고 깃허브 레포에는 올리지 않는다. 회사 보안 구성이 적혀 있기 때문이다.
레포만 받아서 돌리면 파이썬이 없는 새 PC에서 인증서 판정을 건너뛴다.

## 더 읽기

- `docs\CHANGES-ON-THIS-PC.md` — 깔리는 프로그램과 라이브러리와 플러그인, 고쳐지는 설정 파일,
  놓이는 파일과 환경변수를 적어 두었다. 무엇이 내 PC에 들어오는지 확인할 사람을 위한 문서다.
- `docs\DESIGN-NOTES.md` — 인증서를 왜 묻지 않고 재는지, 권한을 왜 한 줄만 여는지, 어떤 대안을
  기각했는지, 테스트가 무엇을 붙잡고 있는지를 적어 두었다. 코드를 고칠 사람을 위한 문서다.
- `certs\README.txt` — `certs\` 폴더를 언제 무엇으로 채우는지 적어 두었다.
- `skills\register-corp-certs\SKILL.md` — 컨테이너와 WSL 안에서 인증서를 다루는 방법을 적어
  두었다.
- `https://github.com/KiwoomAX/KW-doc-formats` — 문서 형식 처리 스킬(`kw-doc-formats:document-formats`)이 사는 플러그인 레포다. 이 설치기가 깔며, 스킬을 고칠 때는 그곳을 고친다.
