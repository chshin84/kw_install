# 설치기가 PYTHONUTF8=1을 세우는 설계 (2026-09-06)

설치기가 사용자 환경변수 `PYTHONUTF8=1`을 세우게 한다.

넷째 판이다. 세 판이 검진에서 무너졌다. 첫 판은 기존 코드가 깨지는 것을 "무관하다"로 닫았고, 둘째 판은 값이 `1`이 아닌 PC를 초록으로 지나갔고, 셋째 판은 **검사 둘이 아무것도 고정하지 못했다.** 기록은 `docs/superpowers/reviews/2026-09-06-pythonutf8-review.md`에 있다.

## 목적

윈도우 파이썬은 `open()`의 기본 인코딩과 표준 입출력을 시스템 코드 페이지에서 가져온다. 한국어 윈도우에서 그 값은 cp949다. 클로드가 UTF-8로 쓴 스크립트가 파일을 열거나 결과를 찍을 때 글자가 깨진다.

`PYTHONUTF8=1`은 파이썬을 UTF-8 모드로 켠다. `open()`의 기본이 UTF-8이 되고 표준 입출력도 UTF-8이 된다.

## 딛고 선 측정

이 PC에서 잰 것이다.

| 무엇 | 값 |
|---|---|
| 사용자 환경변수 `PYTHONUTF8` | `1` |
| 시스템 환경변수 `PYTHONUTF8` | 없음 |
| `sys.flags.utf8_mode` | `1` |
| `locale.getpreferredencoding(False)` | `utf-8` |

**설치기는 이 변수를 모른다.** `setup.ps1`과 테스트와 두 문서를 통틀어 `PYTHONUTF8`이라는 낱말이 한 번도 나오지 않는다. 이 PC의 값은 설치기가 넣은 것이 아니다.

이 작업이 고치는 것은 이 PC가 아니라 **앞으로 세울 PC**다. 지금 설치기로 세운 새 PC는 파이썬이 cp949 기본으로 선다.

## 이 변수가 바꾸는 것

**이 변수는 새 기능을 켜는 것이 아니라 이미 있는 기본값을 뒤집는다.** 아래 두 문단의 "지금"은 **변수가 없는 PC**를 말한다. 이 PC는 사용자가 손으로 세워 두어 이미 UTF-8이다.

**읽기.** 인코딩을 안 적고 cp949 CSV를 읽던 코드는 이 설치 직후 `UnicodeDecodeError`로 끝나거나 글자가 깨진다. 사내에서 오가는 CSV가 대개 cp949라는 것은 `docs/CHANGES-ON-THIS-PC.md`가 `chardet`을 깔며 적어 둔 것이고, 이 회차에서 새로 재지는 않았다.

**쓰기.** `open(path, 'w')`로 CSV를 쓰던 스크립트는 변수가 없으면 cp949로 써서 엑셀이 그대로 연다. 변수가 서면 BOM 없는 UTF-8이 되어 엑셀에서 깨진다.

**사용자가 이것을 알고 세우기로 정했다.** 인코딩을 적는 쪽이 옳고, 적지 않은 코드는 어차피 고쳐야 한다는 판단이다.

**끄는 방법.** 사용자 환경변수 `PYTHONUTF8`을 `0`으로 바꾼 뒤 창을 닫았다 연다. 설치기는 값이 있으면 그대로 두므로 다시 돌려도 `0`이 유지된다. 변수를 **지우면** 다음 실행에서 다시 `1`이 서므로 끄는 방법이 되지 못한다.

## 결정한 것

| 항목 | 결정 | 근거 |
|---|---|---|
| 어디에 세우나 | 사용자 환경변수 (레지스트리) | 관리자 권한이 필요 없고, 설치기가 이미 그 자리에 인증서 변수 넷을 세운다 |
| 현재 세션에도 쓰나 | 안 쓴다 | 이 설치 실행 안에서 이 변수를 읽을 곳이 없다. 실행 도중에 파이썬 모드를 바꾸면 뒤 단계가 띄우는 파이썬의 조건이 달라지는데, 얻을 것이 없다 |
| 언제 세우나 | 3단계 첫머리 | 파이썬을 다루는 단계다. 세션에 안 쓰므로 다른 호출에 영향이 없고, 배치는 사람이 읽기 좋은 자리로만 고른다 |
| `-SkipPythonLibs`와의 관계 | 그 스위치와 무관하게 세운다 | 라이브러리를 안 깔아도 파이썬은 깔린다 |
| 세우기 전에 재나 | **잰다.** 파이썬에게 기본 인코딩을 물어본다 | 재지 않고 세우면 그 변수가 필요했는지 모른 채로 끝난다. 재면 화면과 요약에 무엇을 왜 고쳤는지 적을 수 있다 |
| 무엇으로 재나 | 고정한 3.12에게 `PYTHONUTF8`을 비운 채 `locale.getpreferredencoding(False)`를 묻는다 | 변수를 비우지 않고 재면 이미 선 값 때문에 늘 UTF-8로 보인다. 실측으로 확인했다 |
| 잰 값이 UTF-8이면 | 세우지 않고 초록으로 알린다 | 고칠 것이 없다 |
| 잰 값이 UTF-8이 아니면 | `1`로 세운다 | 이 작업의 목적이다 |
| 재지 못하면 | 세우지 않고 경고로 알린다 | 파이썬이 없거나 대답하지 않는 PC다. 짐작으로 사용자 환경변수를 고치지 않는다 |
| 값이 `1`이면 | 그대로 두고 초록으로 알린다 | 멱등이다 |
| 값이 `0`이면 | 그대로 두고 **초록으로** 알린다 | `0`은 이 문서가 안내하는 끄는 방법이다. 의도된 상태를 경고로 표시하면, 끈 사람이 설치기를 돌릴 때마다 지울 수 없는 경고를 받는다 |
| 값이 `0`도 `1`도 아니면 | 그대로 두되 **경고로** 알린다 | 뜻을 알 수 없는 값이다. 존중하되 목적이 안 이뤄졌음을 숨기지 않는다 |
| `-WhatIfOnly` | 보고만 하고 쓰지 않는다 | 다른 모든 단계와 같다 |
| 함수 이름 | `Set-PythonUtf8Environment` | `Set-CertEnvironment` 옆에 같은 꼴로 둔다 |
| 변수 이름 | 함수 안에 글자로 적는다 | 이름이 하나이고 읽는 곳이 함수 하나다 |

## 함수의 계약

```
Get-PythonDefaultEncoding -PythonExe <경로>
  -> <인코딩 이름 문자열> 또는 $null (못 재면)

Set-PythonUtf8Environment [-Scope User|Process]
  -> @{ Old = <옛 값 또는 $null>; Changed = <bool> }
```

`Get-PythonDefaultEncoding`은 `PYTHONUTF8`을 비운 자식 프로세스에서 잰다. 파이썬이 없거나 대답이 인코딩 이름으로 보이지 않으면 `$null`을 돌려준다. 짐작하지 않는다.

- `Old`는 `[Environment]::GetEnvironmentVariable('PYTHONUTF8', $Scope)`로 읽는다. `Scope`가 정하는 저장소만 본다. 시스템 범위는 어느 쪽에서도 보지 않는다.
- `Old`가 `$null`이면 `1`로 쓰고 `Changed`가 참이다. 부르는 쪽이 읽는 것은 이 둘뿐이라 `Name`과 `New`는 돌려주지 않는다.
- `Old`에 값이 있으면 무엇이든 쓰지 않고 `Changed`가 거짓이다.
- `Scope`가 `User`면 레지스트리에만 쓴다. `Process`면 현재 세션에만 쓴다. 테스트가 `Process`를 쓴다.

## 화면에 무엇을 찍나

3단계 안에서 찍는 것이다. 판정은 `Changed`와 `Old`로 한다.

값이 이미 있으면 재지 않는다. 그 값을 존중하기로 했으므로 재 봐야 할 일이 없다.

| 상태 | 어느 함수로 | 문구 |
|---|---|---|
| 값이 `1`이었다 | `Write-Ok` | `PYTHONUTF8 already 1` |
| 값이 `0`이었다 | `Write-Ok` | `PYTHONUTF8 is 0: left alone, python keeps the system code page` |
| 값이 그 밖이었다 | `Write-Warn2` + `Add-Warning` | `PYTHONUTF8 is '<옛 값>', left alone - python will not default to UTF-8` |
| 값이 없고, 재니 UTF-8이었다 | `Write-Ok` | `python already defaults to utf-8: PYTHONUTF8 not needed` |
| 값이 없고, 재니 그 밖이었다 | `Write-Ok` | `python defaults to <잰 값>: PYTHONUTF8 set to 1` |
| 값이 없고, 재지 못했다 | `Write-Warn2` + `Add-Warning` | `cannot read python default encoding: PYTHONUTF8 not set` |
| `-WhatIfOnly` | `Write-Warn2` | `[WhatIf] would check the python default encoding and set PYTHONUTF8 if needed` |
| 쓰기가 던졌다 | `Write-Warn2` + `Add-Warning` | `PYTHONUTF8 not set: <오류>` |

레지스트리 쓰기가 던질 수 있다. 3단계에는 감싸는 `try`가 없으므로 이 호출만 `try/catch`로 감싼다. 잡은 뒤 `Add-Warning`을 남긴다. 설치기에는 잡고 조용히 넘어가는 `catch`도 있지만, 그것은 판정을 위한 탐색이고 이 자리는 사용자 파일을 고치는 자리다. 고치기에 실패한 것은 알려야 한다.

### 마무리 요약

`Python` 줄 아래에 한 줄을 낸다. 3단계가 정한 상태를 그대로 보인다.

값을 담는 변수는 **지역 변수**다. 3단계와 마무리 요약이 같은 함수 안에 있으므로 스크립트 스코프가 필요 없다. 인증서 요약이 지역 `$doSsl`을 조건식으로 읽는 것과 같은 꼴로 둔다.

값은 `set to 1 (was <잰 값>)`·`not needed (already utf-8)`·`already 1`·`0 (left alone)`·`'<옛 값>' (left alone)`·`not set (<사유>)` 가운데 하나다. `-WhatIfOnly`면 `not touched`다.

**리터럴로 박지 않는다.** 요약이 실제 결과와 무관하게 무언가를 주장하면 안 된다. 그것을 어떻게 검사할지는 아래 「검사는 구현에서 확정한다」를 따른다.

## 테스트

검사는 두 종류다. 함수를 부르는 것과 `setup.ps1` 원문을 훑는 것이다.

### 함수를 부르는 검사

`-Scope Process`에서 잰다. 레지스트리를 건드리지 않는다. **블록의 처음과 끝에서 프로세스 환경의 `PYTHONUTF8`을 비운다.** 처음에 비우는 이유는 이 PC의 사용자 값 `1`이 테스트 프로세스로 상속되어 "없던 자리"가 아니게 되기 때문이다. 끝에서 비우는 이유는 이 블록이 값을 남기는데 뒤쪽 검사들이 파이썬을 띄우기 때문이다. 그 검사들이 다루는 것은 ASCII뿐이라 지금은 영향이 없지만, 검사가 자기 자리를 치우는 것이 규율이다.

- 없던 자리에 부르면 `Changed`가 참이고 값이 `1`이다.
- 두 번째로 부르면 `Changed`가 거짓이고 값이 `1` 그대로이며 `Old`가 `1`이다.
- `0`을 넣고 부르면 `Changed`가 거짓이고 값이 `0`으로 남으며 `Old`가 `0`이다.

### 원문을 훑는 검사 — 구현에서 확정한다

`Find-Phase`로 3단계 본문을 잘라 낸 `$libsPhase`에서 본다. **어떤 식으로 볼지는 이 문서에서 정하지 않는다.**

앞 네 판에서 이 표를 산문으로 적었고 네 번 다 헐거웠다. 셋째 판의 검사 둘은 코드를 한 줄도 안 넣어도 통과했고, 넷째 판의 검사 셋은 실행식이 아니거나 정규식이 틀렸다. 검진이 뿌리를 짚었다. 무엇을 검사할지는 회차마다 나아지는데, 그 검사가 무엇을 통과시키는지를 문서가 스스로 반증해 보지 않는다.

**그래서 구현에서 확정한다.** 아래 여섯 가지를 검사로 만들되, 식을 쓸 때마다 **그 식을 통과하면서 기능이 없는 구현을 실제로 세워 본다.** 세워지면 그 식을 버리고 다시 쓴다.

| 무엇을 고정하나 |
|---|
| 3단계가 함수를 부른다 |
| `-SkipPythonLibs` 분기 바깥에서 부른다 |
| 뜻 모를 값을 조용히 지나가지 않는다 |
| `0`은 경고로 올리지 않는다 |
| 마른 실행이 레지스트리를 안 건드린다 |
| 마무리 요약이 실제 결과를 읽는다 |
| 재고 나서 세운다 |
| 못 재면 세우지 않는다 |

기존 테스트가 참고할 꼴을 셋 갖고 있다. 순서를 재는 `$libsPhase.IndexOf(...)` 비교, 마른 실행 가드를 원문에서 보는 `'\$pyDir -and -not \$WhatIfOnly'`, 요약이 조건식을 읽는지 보는 `'Cert variables\s*:\s*\$\(if \(\$doSsl\)'`이다. 셋 다 통과하면서 기능이 없는 구현을 세우기 어렵다.

정규식을 큰따옴표 안에 쓸 때 `$`는 백틱으로 막는다. 기존 검사가 그렇게 한다.

### 이 회차가 재지 못하는 것

`-Scope User`로 레지스트리에 실제로 쓰는 경로는 이 회차에서 실행되지 않는다. 테스트가 `Process`만 쓰고, 이 PC는 이미 `1`이라 설치기가 세운 것인지 원래 있던 것인지 갈리지 않는다. **이 경로의 확인은 다른 PC에서 설치기를 처음 돌릴 때 한다.** 그때 사용자 환경변수에 `1`이 서고 화면에 `set to 1`이 찍히는지 본다. 이 회차의 검진 기록에 그 확인이 남았다고 적지 않는다.

## 고칠 스킬

플러그인 레포 `KiwoomAX/KW-doc-formats`의 `skills/document-formats/SKILL.md`가 이 변수와 어긋나는 문장을 셋 들고 있다.

**고치는 방향이 셋째 판과 다르다.** 셋째 판은 "기본이 UTF-8"로 바꾸려 했는데, 값이 `0`이거나 뜻 모를 값이어서 변수가 안 서는 PC에서는 그것도 거짓이다. 스킬은 PC별로 갈리지 않고 한 벌로 배포된다. **그러니 기본값이 무엇인지를 단정하는 문장을 아예 없앤다.** 어느 PC에서든 참인 문장으로 바꾼다.

| 행 | 지금 | 바꿀 문안 |
|---|---|---|
| 104 | 이 PC의 기본값이 cp949라 그냥 두면 읽는 쪽에서 멈춘다 | 기본 인코딩은 PC마다 다르니 `encoding=`을 적지 않으면 읽는 쪽에서 멈질 수 있다 |
| 129 | **이 PC에서 파이썬이 파일을 열 때 쓰는 기본 인코딩은 cp949다.** | **파이썬이 파일을 열 때 쓰는 기본 인코딩은 PC마다 다르다.** 윈도의 로케일과 `PYTHONUTF8` 환경변수가 함께 정한다. 그러니 기본값에 기대지 말고 `encoding=`을 적는다. 지금 이 PC의 값은 `python -c "import locale;print(locale.getpreferredencoding(False))"`로 확인한다. |
| 146 | 다만 환경변수는 그 실행에만 붙으므로 | 다만 그 변수는 PC마다 있을 수도 없을 수도 있으므로 |

**인코딩을 적으라는 규칙은 그대로 둔다.** 오히려 근거가 튼튼해진다. 기본값이 PC마다 다르니 적어야 한다는 것이 어느 PC에서든 참이다.

`chardet`으로 판별해 읽으라는 규칙도 그대로다. 사내에서 **받는** 파일이 cp949인 것은 이 변수와 무관하다.

**푸시 순서.** 스킬을 먼저 올린다. 바꿀 문안이 어느 PC에서든 참이므로, 설치기가 아직 안 나간 구간에서도 스킬이 거짓을 말하지 않는다. 이것이 이번 문안 변경으로 얻은 것이다. 셋째 판의 문안("기본이 UTF-8")이었다면 어느 쪽을 먼저 올려도 거짓인 구간이 생겼다.

## 순서

1. 이 레포의 테스트에 검사 아홉을 더하고 실패를 본다. 원문 검사는 식을 쓸 때마다 그 식을 통과하면서 기능이 없는 구현을 세워 보고, 세워지면 다시 쓴다.
2. `setup.ps1`을 고친다. 함수, 3단계 배선, 요약 지역 변수, `.DESCRIPTION`, 마무리 요약을 한 번에 한다.
3. CRLF를 정규화하고 테스트를 돌린다. 기준선 다섯만 실패해야 한다.
4. 이 레포의 문서 둘을 고친다.
5. 플러그인 레포의 스킬 세 자리를 고쳐 커밋하고 푸시한다.
6. 이 레포를 커밋하고 푸시한다.

## 남는 위험

- **인코딩을 안 적은 기존 코드가 깨진다.** 사용자가 알고 정한 것이지만, 어느 스크립트가 걸리는지는 이 레포 밖이라 세지 못했다.
- **값이 `0`이거나 뜻 모를 값인 PC에서는 변수가 영영 안 선다.** 사용자 값을 존중한다는 결정의 값이다. `0`은 의도된 것으로 보아 초록으로, 그 밖은 경고로 알린다.
- **레지스트리에 실제로 쓰는 경로가 이 회차에서 실행되지 않는다.** 다른 PC에서 처음 돌릴 때 확인한다.
- **이미 열려 있는 창은 이 변수를 못 받는다.** 새 창을 열어야 한다. README가 모든 환경변수에 대해 이미 안내한다.
- **`PYTHONIOENCODING`이 이미 서 있는 PC에서는 표준 입출력이 그쪽을 따른다.** 이 설계는 그 변수를 세우지도 지우지도 않는다.

## 하지 않는 것

- 시스템 환경변수로 세우지 않는다. 관리자 권한이 필요하고 다른 사용자에게도 걸린다.
- 콘솔 코드 페이지를 바꾸지 않는다. `setup.cmd`로 시작하면 `chcp 65001`이 돌고, 그러지 않은 실행에서도 마무리 안내를 읽을 때 `setup.ps1`이 그 프로세스의 출력 인코딩만 UTF-8로 맞춘다. 사용자가 나중에 여는 창의 코드 페이지는 어느 쪽도 건드리지 않으며 이 작업의 범위 밖이다.
