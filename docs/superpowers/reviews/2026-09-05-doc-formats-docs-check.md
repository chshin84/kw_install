# 문서 검진 기록 — 플러그인 분리 뒤의 README와 변경 문서 (2026-09-05)

`README.md`와 `docs/CHANGES-ON-THIS-PC.md`를 `lens-grounding`과 `lens-readability`로 한 회차 검진했다. 한 서브에이전트가 두 렌즈를 차례로 적용했고, 렌즈를 한 번씩만 돌렸다. 렌즈 원본은 이 파일과 같은 이름의 폴더에 있다.

readability에 준 목적은 "클로드 코드를 써 본 적 없는 새 PC 담당자가 이 문서만 보고 설치를 끝까지 마치고, 실패했을 때 무엇이 잘못됐는지 스스로 가려내게 한다"였다.

## 고친 것

이번 분리 작업이 만든 어긋남이라 그 자리에서 고쳤다.

| 지적 | 렌즈 | 처분 |
|---|---|---|
| 고치는 사용자 파일의 수가 README는 다섯, CHANGES는 넷이다. 차이는 `.curlrc`다 | grounding | CHANGES를 다섯으로 맞추고 `.curlrc`를 열거에 넣었다 |
| CHANGES가 `.curlrc`를 셈에서 빼 놓고, 같은 문서 뒤쪽 표에서 그 파일의 백업 예외를 설명한다 | grounding | 위와 같은 수정으로 함께 풀렸다 |
| CHANGES의 스킬 행이 옛 사본을 조건 없이 지운다고 적는다. 실제로는 플러그인 설치가 확인되고 폴더에 `SKILL.md` 하나만 있을 때만 지운다 | grounding | 두 조건과 어긋났을 때의 처리를 행에 적었다 |
| README의 「이 PC에 생기는 변화」 문단이 파일 다섯을 한 문장에 늘어놓고 "앞의 넷"으로 되짚게 한다 | readability | 목록으로 끊고 되짚기를 없앴다 |
| CHANGES의 열거 순서가 그 절의 본문 순서와 다르다 | readability | 본문 차례에 맞췄다 |
| CHANGES의 `kw-doc-formats` 행이 자동 갱신 설명을 다른 절과 겹쳐 적는다 | readability | 겹치는 문장을 덜고 그 절을 가리켰다 |

## 고치지 않고 사용자에게 알린 것

이번 작업이 만든 것이 아니라 원래 있던 자리다. 고치려면 사실 판단이나 문서 구조 결정이 필요해 사용자에게 넘긴다. 상세는 그날의 최종 보고에 적었다.

- README가 `python -m playwright install chromium`을 이름 대는데, 그 명령이 필요로 하는 파이썬 `playwright` 패키지는 `requirements.txt`에 없다.
- 「잘 안 될 때」 절이 「설치 단계」 절보다 앞에 있어, 종료 코드 표가 아직 소개되지 않은 단계 이름을 가리킨다.
- 「설치 단계」 표에 화면 번호 열이 없어, 번호를 줄 차례로 옮기는 셈법을 세 문장으로 설명한다.
- 금지 표현이 README 세 곳과 CHANGES 네 곳에 남아 있다.
- 종료 코드 3의 세 갈래를 화면 어디서 가리는지 적혀 있지 않다.
- 「더 읽기」가 깃허브 레포에 없는 두 파일을 단서 없이 가리킨다.
- CHANGES의 설정 표 한 열에서 말끝이 한 칸만 다르다.

## 검진 밖에서 렌즈가 남긴 관측

`setup.ps1`의 머리말 단계 목록이 낡았다. 인증서 단계를 아직 "asked for with Y/N at launch"라 적는데 지금은 측정으로 판정하고, 프로그램 단계 목록에서 Poppler가 빠져 있다. 그리고 `.PARAMETER ClaudeJsonPath`가 설명하는 `$ClaudeJsonPath`는 기본값이 정해진 뒤 어디서도 쓰이지 않는다. 셋 다 이번 검진 대상 밖이라 고치지 않았다.
