# spec 검진 기록 — PYTHONUTF8=1 (2026-09-06)

검토 대상은 `docs/superpowers/specs/2026-09-06-pythonutf8-design.md`다. 렌즈를 한 번씩만 돌렸다. 한 서브에이전트가 grounding과 consistency를 차례로 적용했고 adversarial은 자세가 반대라 따로 띄웠다. 렌즈 원본은 이 파일과 같은 이름의 폴더에 있다. 선행연구 렌즈는 제안하지 않았다. 환경변수 하나를 세우는 일이라 발동 기준에 걸리지 않는다.

## 사용자에게 올린 것

검진이 이 작업의 전제를 흔들었다. `PYTHONUTF8=1`은 `open()`의 기본 디코더를 cp949에서 UTF-8로 바꾸므로 **지금 되던 것을 깨뜨릴 수 있다.**

- 인코딩을 안 적고 사내 cp949 CSV를 읽던 코드가 이 설치 직후 실패하거나 글자가 깨진다.
- `open(path,'w')`로 CSV를 쓰던 스크립트가 BOM 없는 UTF-8을 내어 엑셀에서 깨진다.

첫 판 spec은 이것을 "무관하다" 한 줄로 닫았다. 틀렸다. 팀의 기존 스크립트가 인코딩을 적고 있는지는 이 레포 밖의 사실이라 사용자에게 올렸고, **사용자가 그래도 세우기로 정했다.** 대신 무엇이 바뀌는지와 끄는 방법을 문서에 적는다.

## 고친 것

| 지적 | 렌즈 | 처분 |
|---|---|---|
| cp949 읽기·쓰기가 깨지는 길을 "무관하다"로 닫았다 | adversarial | 위험으로 올리고 문서에 적는다 |
| 스킬이 "이 PC 파이썬 열기 기본은 cp949"라고 단정한다 | adversarial·grounding | 스킬 고치기를 범위에 넣는다. 세 자리다 |
| 사용자가 `0`으로 둔 값을 덮기로 했다 | adversarial | 덮지 않는다. 설치기의 다른 자리와 같게 존중한다 |
| 되돌리는 길이 없다 | adversarial | 끄는 방법을 문서에 적는다 |
| 계약이 본뜬 함수보다 크다 | adversarial·grounding | `Set-CertEnvironment`와 같은 모양으로 줄인다 |
| "실패할 자리가 없다"면서 `try/catch`를 둔다 | adversarial·consistency | 잡고 `Add-Warning`을 남긴다 |
| 배치 검사가 `else` 안에 들어가도 통과한다 | adversarial·consistency | 기존 테스트처럼 `IndexOf`로 순서를 잰다 |
| 1·2단계가 이미 파이썬을 부른다 | adversarial | 근거를 고친다 |
| "PowerShell 7은 이미 UTF-8 기본"이 틀렸다 | adversarial·grounding | 근거를 고친다 |
| 테스트가 환경변수를 먼저 비우지 않는다 | grounding | 비우는 걸음을 더한다 |
| 화면 문구의 출력 함수가 미정이다 | grounding·consistency | 정한다. 꼴도 하나로 맞춘다 |
| ASCII·CRLF 제약을 안 적었다 | grounding | 적는다 |
| 변수 이름의 정본 자리가 없다 | consistency | `$script:PythonUtf8Name`을 둔다 |
| 마무리 요약에 나오는지 미정이다 | consistency | 나오게 한다 |
| `setup.ps1`의 단계 목록이 고칠 자리에서 빠졌다 | consistency | 더한다 |
| 「하지 않는 것」에 중복이 있다 | consistency | 뺀다 |

## 이 회차가 남기는 것

검진이 아니었으면 기존 스크립트가 깨지는 것을 모른 채 내보냈을 것이다. 환경변수 하나를 세우는 작은 일로 보였는데, 그 변수가 바꾸는 것은 이 PC의 모든 파이썬 코드의 기본값이었다.

## 둘째 회차 (같은 날)

세 렌즈를 한 호출에 묶어 둘째 판을 봤다. 첫 판의 처분 열여섯 가운데 열넷이 고쳐졌고 셋이 부분만 고쳐졌다. 새로 열일곱을 잡았다. 원본은 같은 폴더의 `round2-lenses.json`에 있다.

**가장 무거운 것.** 값이 `1`이 아닌 채로 있는 PC에서 설치기가 그것을 초록 한 줄로 지나간다. 사용자 값을 존중하기로 한 결정의 결과인데, 그러면 몇 번을 돌려도 파이썬이 cp949로 서고 화면에도 마무리 경고에도 흔적이 없다. 목적이 안 이뤄진 것을 알리지 않는 것은 설치기의 다른 자리와 어긋난다.

고친 방향은 이렇다. 값이 없으면 세우고, `1`이면 그대로 두고 초록으로 알리고, **`1`이 아닌 다른 값이면 그대로 두되 경고로 알린다.** 존중과 알림을 함께 한다.

**그 밖에 고친 것.** 끄는 방법 둘 중 지우기는 다음 실행에 풀린다는 것, 테스트가 `0`을 남겨 뒤 검사의 파이썬 모드를 바꾸는 것, 실행 뒤 값이 실제로 섰는지 재는 자리가 없는 것, 설치 중에 읽을 데 없는 변수를 세션에 쓰는 것, 상수 하나가 과한 것, `PYTHONIOENCODING` 서술의 모순, 순서의 테스트 공백, 근거 문장 넷의 사실 오류다.

## 셋째 회차 (같은 날)

둘째 회차의 열일곱 가운데 열셋이 고쳐졌고 넷이 남았다. 새로 열여섯을 잡았다. 원본은 같은 폴더의 `round3-lenses.json`에 있다.

**가장 무거운 것.** 내가 쓴 검사 둘이 아무것도 고정하지 못한다. 「3단계 본문이 `Write-Warn2`와 `Add-Warning`을 둘 다 부르는 자리를 갖는다」는 검사는 코드를 한 줄도 안 넣어도 통과한다. 3단계에 이미 그 둘이 여러 번 나오기 때문이다. 「마무리 요약에 `PYTHONUTF8`이 있다」도 글자만 박으면 통과한다. 인증서 쪽 요약 검사는 조건식까지 본다.

**둘째로 무거운 것.** 「실행 뒤 확인」이 `-Scope Process`로 함수를 부르는데, 그 경로는 레지스트리에 쓰는 분기를 한 번도 실행하지 않는다. 둘째 회차가 "재는 자리가 없다"고 지적한 것을 재는 자리를 만들지 않고 이름만 붙였다.

**설계의 긴장 하나.** 문서가 권한 끄는 방법(`0`으로 두기)이 문서가 경고로 표시하는 상태와 같다. `0`으로 끈 PC는 설치기를 돌릴 때마다 노란 줄과 마무리 경고를 하나씩 받고, 그것을 없앨 방법이 설계 안에 없다.

**스킬 쪽의 새 문제.** 스킬 문장을 "기본이 UTF-8"로 바꾸면 값이 `1`이 아니어서 변수가 영영 안 서는 PC에서 거짓이 된다. 스킬은 PC별로 갈리지 않고 한 벌로 배포된다.

## 넷째 회차 (같은 날) — 그리고 이 spec을 멈추는 이유

셋째 회차의 열여섯 가운데 열셋이 고쳐졌다. 렌즈가 "처음으로 잘 수렴한 판"이라고 적었다. 원본은 같은 폴더의 `round4-lenses.json`에 있다.

그런데 세 자리를 계속 맴돈다. 검사가 아무것도 고정하지 못하고, 요약이 리터럴을 통과시키고, 「하지 않는 것」에 중복이 남는다. 렌즈가 뿌리를 짚었다.

> 이 문서는 '무엇을 검사할지'는 매 회차 더 잘 적지만 '그 검사가 무엇을 통과시키는지'를 스스로 반증해 보지 않는다.

**그래서 이 spec을 여기서 멈춘다.** 환경변수 하나를 세우는 일에 네 판을 썼고, 남은 지적 열넷 가운데 다섯이 검사식 자체의 문제다. 산문으로 검사를 적는 것을 계속하면 다섯째 판도 같은 자리를 맴돈다.

**남은 것은 구현에서 푼다.** 검사를 실제 PowerShell 식으로 쓰고, 각 식마다 **그 식을 통과하면서 기능이 없는 구현을 실제로 세워 본다.** 세워지면 그 검사는 버리고 다시 쓴다. RED를 실제로 돌리는 것이 산문보다 정확하다. 그것이 TDD가 하는 일이다.

이 회차의 사실 오류 다섯(스킬 129행 문안, 콘솔 근거, pip check 근거, 계약의 `New`, 요약 변수의 스코프)은 spec에 반영하고 멈춘다.
