# 문서 검진 기록 — claude_pack (2026-08-16)

`reviewer-grounding`과 `reviewer-fit`을 각각 한 번씩 읽기 전용 서브에이전트로 띄워 받은 지적과,
그것을 어떻게 처분했는지를 적는다. 기록이 없으면 지적이 0건이었던 검진과 지적을 전량 넘긴
검진이 구별되지 않는다.

## 검진 대상

이 세션에서 고친 문서 셋이다.

- `skills/document-formats/SKILL.md`
- `templates/personal-memory-ko.md`
- `README.md`

두 렌즈 모두 바뀐 줄에 머물지 않고 문서 전체를 봤으므로, 아래에는 이번에 손대지 않은 곳의
지적도 섞여 있다.

## 고친 것

각 항목은 코드나 실측과 맞대어 사실인지 먼저 확인한 뒤 고쳤다.

| 무엇이 틀렸나 | 어떻게 고쳤나 |
|---|---|
| 권한 표가 `PowerShell(*)`와 `Bash(*)`를 `allow`에 넣는다고 적었다. 설치기는 `permissions` 아래에 `defaultMode` 하나만 쓴다 | 표의 두 행을 실제 동작으로 바꾸고, 이전 판과 무엇이 달라졌는지 문단으로 덧붙였다 |
| 테스트가 검사한다고 적은 것 중 넓힌 권한 규칙·SSL `ask` 관문·`.claude.json` 수락 키는 존재하지 않는다 | 실제 검사 목록으로 다시 썼다. 권한은 '부재로 고정'한다는 실제 방식으로 고쳤다 |
| 뮤테이션 증거로 든 `Bash(curl -k *)` 규칙이 테스트에 없고, 단언 개수도 실제와 다르다 | 재현되지 않는 예를 빼고, 개수를 문서에 박지 않기로 했다. 계약은 `FAIL=0` 하나다 |
| `templates\개인기억.md`라는 파일이 없고, `templates\`를 '참고 문서'로 적었다. 실제로는 실행 중 읽히는 입력이다 | 실제 파일명과 역할로 고쳤다. 지웠을 때 무엇이 죽는지도 적었다 |
| 설치기가 사용자 `CLAUDE.md`를 고치고 `.bak`을 만드는데 어느 표에도 없다 | 변경 대상이 두 파일임을 밝히고, 관리 영역과 백업 동작을 적었다 |
| 가로채기가 없으면 '경고도 남기지 않는다'고 적었으나 노란 줄이 남는다 | 무엇이 빠져서 노란 줄이 남는지로 고쳤다 |
| 1단계를 '있을 때만' 번들을 굽는다고 적어, 판정 불명일 때 굽는 동작과 어긋난다 | '필요하다고 판단되면'으로 고쳤다 |
| 종료 코드 표에 더블클릭 진입점이 내는 9가 없다 | 표에 넣었다 |
| 팩 크기를 158KB로 적었으나 실측 171KB다 | 손으로 맞춰야 하는 숫자를 빼고 근거만 남겼다 |
| '이유가 없는 항목은 두지 않는다'고 선언하고 네 행의 비고를 비웠다 | 선언을 실제 관행에 맞추고, 판 제약이 걸린 `pandas<3.0`에는 이유를 채웠다 |
| 플러그인 표가 둘이고 설명이 서로 다르다 | 뒤 표를 없애고 정본을 가리키게 했다 |
| 파일 목록에 `setup.cmd`가 없다 | 넣었다 |
| `###` 제목 앞에 빈 줄이 없어 절이 목차에서 빠질 수 있다 | 빈 줄을 넣었다 |
| `SKILL.md`가 절을 '아래 두 절'처럼 위치로 가리킨다 | 절 이름으로 부르게 고쳤다 |
| `## PDF`·`## 구형 워드·PPT`·`### 남는 차이 하나`가 언제 펴 보는지 알려 주지 않는다 | 발동 조건이 드러나는 이름으로 바꿨다 |
| 테마 비교표의 첫 칸이 비어 있고 열 머리가 XML 조각이다 | 축 이름을 달고 셀을 알아볼 수 있는 구로 채웠다 |
| 사내 CSV가 cp949라는 사실과 그 때문에 깐 `chardet`이 스킬에 없다 | `.csv` 단서와 판별 코드를 넣었다 |

## 코드까지 간 것

근거 렌즈가 8단계 검증이 회사망 밖에서 통째로 건너뛰어진다는 것을 잡았다. 문서가 반대로
적고 있었으므로 문서만 고치면 결함이 남는다. 실패하는 테스트를 먼저 세우고 코드를 고쳤다.
번들이 없으면 이 PC의 기본 신뢰로 붙어 보고, 무엇으로 붙었는지를 `Forced`로 구분해 보고한다.

## 뒤이어 별건으로 고친 것

처음에는 넘겼다가 사용자가 진행을 지시해 같은 날 마무리한 것들이다.

- **README에 단계마다 매긴 0부터 8까지의 서수 번호.** 단계를 이름으로 부르도록 바꾸고, 본문
  열한 곳의 '2단계'·'1번' 같은 참조를 전부 이름으로 고쳤다. 화면에는 여전히 번호가 찍히므로
  그것이 표시 순서일 뿐이라는 것을 한 번 밝혀 두었다.
- **README의 독자 분리.** 설계 근거를 `docs/DESIGN-NOTES.md`로 옮겼다. README에는 새 PC를
  세우는 담당자가 필요한 것만 남기고, 왜 그렇게 만들었는지와 기각한 대안은 그쪽으로 보냈다.
  옮긴 내용이 빠지지 않았는지는 특징적인 문구를 대조해 확인했다.
- **단계 표 '하는 일' 칸의 명사 나열.** 완결된 문장으로 고쳤다.

  사용자 결정 사항이다. 넘기고 사용자에게 알렸다.

보이나 이번 변경으로 불필요해진 것이 아니므로 지우지 않고 표시만 해 둔다.
